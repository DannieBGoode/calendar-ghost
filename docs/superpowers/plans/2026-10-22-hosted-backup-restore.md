# Hosted backup and restore Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The owner has chosen this method. Stop for owner review before product code.

**Goal:** Ship optional continuous SQLite backup guidance and a safe offline inspection and conservative restore command.

**Architecture:** A separate bootstrap entry composes a small Operations service, a SQLite adapter, and a terminal interface. Pure domain decisions choose the closed Registration Policy and eligible recovery administrator. No API container, scheduler, Instant Sync loop, mail worker, or provider adapter is constructed.

**Tech Stack:** Python 3.12, argparse/getpass, existing SQLite connections and security adapters, optional Litestream v0.5.17.

**Spec:** [Open registration design](../specs/2026-10-20-open-registration-design.md), full Hosted Service backup runbook, delivery slice 5, and approved backup decisions; [ADR 0029](../../adr/0029-isolate-users-in-one-sqlite-database.md).

## Global Constraints

- Work from fetched `origin/main`; preserve the workspace branch name. At planning time both point to `4d8d0cb2`, and there are no open PRs.
- No migration is needed. Supported migration ledger is exactly versions 1 through 39. Latest ADR is 0041. Fetch and check both again before implementation; never silently accept a new schema.
- Keep import-linter contracts unchanged, constructors within seven fields, and no new WIDE_DATACLASSES entry or complexity suppression.
- Open SQLite only through `infrastructure/persistence/connections.py`. Inspection never calls `initialize_database`, creates a database, or migrates it.
- No mandatory backup service, remote dependency in standard Compose, public maintenance endpoint, scheduler mode, billing, or Plan Hold edits.
- Preserve rules, mappings, incremental positions, Plan settings, assignments, grace, admission counters, and all Plan Hold fields.
- Use synthetic fixtures. Output counts and fixed status codes only; no passwords, email addresses, tokens, credentials, event content, or raw exception text. No em dashes.
- Preparation requires stopped application and Litestream processes, closed ingress, and explicit acknowledgement. A SQLite lock does not prove a sleeping process is stopped.

## Review Focus

1. A wrong key, corrupt credential, or partial/future schema must fail before any preparation write (Task 1 tests).
2. An unwritable, aliased, existing, or interrupted backup destination must leave authority unchanged and never overwrite the earlier backup (Task 2 tests).
3. Revived provider sign-in and Watch Notice proofs must remain unusable after preparation, including repeat attempts (Task 2 tests).
4. Terminal fallback, EOF, and failure messages must never echo secrets or start runtime services (Task 3 tests).
5. Retention compaction and VACUUM can change restore endpoints; verify actual restored state across each boundary, rather than process uptime or file existence (Task 4 evidence).

## Decisions recommended for owner review

- Expose `calendar-ghost-restore inspect --database PATH` and `calendar-ghost-restore prepare --database PATH --backup PATH --administrator-id ID --acknowledge-services-stopped`.
- Read the existing `CALENDAR_SYNC_MASTER_KEY` environment variable only; accept no key/password command-line argument. Require a well-formed key for both inspect and prepare, including factory construction. Missing/malformed keys fail with `key_missing`/`key_invalid`, status 1. `authenticated_credentials == 0` means `key_unverified`; a positive count means `key_authenticated`. An empty database cannot prove key matching.
- Ship only the conservative prepare path. Comparison/replay remains an operator procedure, with no automatic trusting mode or administrator-action ledger.
- A selected existing Installation Administrator may be active or disabled. Explicit selection reactivates that administrator; all other Users become disabled. Never create a User or change a role/email/Local Email Verification marker.
- Remove every Provider Identity and disable every provider sign-in setting. Deleting bindings alone allows automatic linking again through restored verified email. Confirm the administrator's current email and recovery mailbox ownership before reopening ingress; provider sign-in requires that check and explicit administrator enablement.
- Keep an already closed Registration Policy. Close Open to Only Me for exactly one User, otherwise Invitation Only. Count all Users, including disabled ones.
- Litestream v0.5.17 is the current release checked on 2026-10-22, not yet tested here. Pin that version and the release asset checksum in the evidence. Do not label it tested until Task 4 passes.
- Targets: healthy remote recovery point within 1 minute; alert after 5 minutes of unsuccessful replication; 30-day recovery history; recovery within 30 minutes; monthly isolated restore drill. Record measured results and sample size, with no availability or recovery guarantee.
- Keep daily independent recovered SQLite snapshots for 720 hours after capture, plus continuous replication. Advertise daily historical restore points, not arbitrary second-level recovery throughout 30 days.
- No new ADR is proposed: this implements the approved design. Document the narrow offline cross-User exception beside ADR 0029's existing exceptions and in architecture.
