# Open Registration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox syntax for tracking. The owner chose this method; do not ask again.

**Goal:** Let people join through verified email when an Installation Administrator explicitly chooses Open, while preserving Only Me and Invitation Only.

**Architecture:** Pure domain decisions govern admission and proof usability. Narrow Identity ports perform atomic SQLite mutations; the existing bounded identity mail worker sends proofs outside transactions. Reuse the context modules, session race guard, readiness, and Default Plan behavior.

**Tech Stack:** Python 3.12, SQLite, FastAPI/Pydantic, React/TypeScript, pnpm 12. No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-20-open-registration-design.md`, remaining delivery slice 3; ADR 0040, ADR 0030, ADR 0029, ADR 0028; attached owner brief.

## Global constraints and exact values

- Only Me remains the fresh/upgrade default. Open requires explicit administrator choice and matching successful identity test. Plans remain independent and off by default; no billing, OIDC, backup tooling, synchronization or Plan Hold edits.
- New records have SQLite adapters only. No edits to `persistence/memory.py`; no new installation-wide UOW receiver. Domain imports no ports/adapters. Keep import contracts unchanged; add no `WIDE_DATACLASSES` entry and remove `AcceptInvitation` once reduced to seven fields; constructors at most seven fields, no complexity suppressions.
- Tokens use 32 random bytes; persist SHA-256 hashes only. Link lifetime 24 hours, capped by the original Invitation's 7-day expiry. Preserve delivered sibling links until completion; consume all registration siblings for the email atomically.
- Request limits: email 5/hour with 60-second cooldown; email/network pair 2/hour; network 20/15 minutes; installation 100/hour. Invalid checks 20/network/15 minutes; password completions 10/network/15 minutes, including valid proofs. Never refund on success.
- IPv4 address or IPv6 /64; bounded front gate of 10,000 live networks, refuse new keys at capacity. Separate sign-up/reset allowances, keys and queue capacity. Count admitted unknown/disabled addresses before eligibility lookup.
- Before storage or hashing: body at most 8 KiB; normalized email at most 254 characters; tokens at most 128 ASCII characters; verified-registration passwords 12 to 1,024 characters. Preserve direct Invitation/setup/new-password bounds and existing sign-in/current-password 1,024 bound.
- New anonymous SQLite reads/writes wait at most 100 ms. Fresh clock and eligibility under the final write lock. Hashing, SMTP and session creation outside that lock. No account lookup or SMTP awaited by request handlers.
- Queues: sign-up 50, reset 50, security/test 10 waiting requests; one SMTP thread, fair turns across nonempty lanes, existing 10-second timeout, no retry/outbox. Queue rejection/failure retains generic acceptance.
- Tokens only in URL fragments and bounded POST bodies; no-store/no-referrer on identity pages/responses, including errors. No secrets, addresses, passwords, bodies, account eligibility or provider exception text in logs.
- Remove expired/used/revoked proofs and obsolete counters within 24 hours while running, without the scheduler. Batches at most 500; reserve 250 each for proofs and counters, yielding between batches. Read-only checks never purge proofs.
- All UI copy through `t()`, values through `i18n.format`, plural numbers as `count`; no em dashes. Follow `DESIGN.md`, existing AuthFrame and password fields. Rebuild/commit static assets with every web change.

- `RegistrationProof(token_hash: str, email: str, expires_at: datetime, invitation_id: str | None = None, used_at: datetime | None = None, revoked_at: datetime | None = None)`; `usable(at: datetime) -> bool`.
- `may_issue_invitation(policy: RegistrationPolicy) -> bool`; `may_accept_invitation_directly(policy: RegistrationPolicy) -> bool`; `may_finish_registration(policy: RegistrationPolicy, invitation_bound: bool, operational: bool) -> bool`; `registration_expiry(at: datetime, invitation_expires_at: datetime | None = None) -> datetime`.
- `PendingRegistration(email: str)`; `PreparedRegistration(recipient: str, link: IssuedLink)`; `RegistrationEmailRequest(email: str, fingerprint: str, invitation_token: str | None = None)`. Hide recipient, token and email fields from repr.
- `OpenRegistrationStatus(available: bool, reason: Literal["identity_email_not_configured", "identity_email_not_tested"] | None)`; `RegistrationReadiness.status() -> OpenRegistrationStatus`, `public_available() -> bool`. Read current policy/readiness through a short SQLite read, no User lookup.
- `Invitations.accept(token: str, email: str, password_hash: str) -> User | None`; the adapter owns ID/time and final policy/expiry checks. `AcceptInvitation` retains users/settings/invitations/passwords/sessions/clock/attempts (seven fields), dropping IDs.
- `RegistrationSettings.set_policy(policy: RegistrationPolicy, *, actor: UserId, fingerprint: str | None) -> None`. Keep `policy()` and `return_to_setup(at)` signatures. `SetRegistrationPolicy` gets immutable fingerprint from bootstrap, never the caller.
- `RegistrationProofs.issue(email: str, invitation_token: str | None, fingerprint: str) -> PreparedRegistration | None`; `check(token: str, fingerprint: str | None) -> PendingRegistration | None`; `complete(token: str, password_hash: str, fingerprint: str | None) -> User | None`; `purge(before: datetime, limit: int) -> int`.
- `RegistrationUnavailable` signals temporarily non-operational Open; `RegistrationStorageUnavailable` signals failed reads/writes. `OpenRegistrationUnavailable(reason)` signals refused administrator Open selection, with the two readiness reasons above. Define these application errors in `registration_ports.py`. `check`/`complete` raise `RegistrationUnavailable` only after verifying a live proof and allowed policy when readiness alone fails; return `None` for expired/used/revoked/cross-purpose proofs or policy closure. Never revoke a proof merely because readiness is lost.
- `RegistrationAdmission.admit_front(client: str) -> None`, `admit_durable(email: str, client: str) -> bool`, `check_token(client: str, check: Callable[[], bool]) -> bool`, `admit_completion(client: str) -> None`, `purge(before: datetime, limit: int) -> int`. Same gate order as reset; separate typed registration throttle/storage failures.
- `RequestRegistration.execute(email: str, client: str, invitation_token: str | None = None) -> None`; `CheckRegistration.execute(token: str, client: str) -> PendingRegistration | None`; `CompleteRegistration.execute(token: str, password: str, client: str) -> Session`.
- `RegistrationMaintenance(delivery: DeliverRegistration | None, proofs: RegistrationProofs, admission: RegistrationAdmission)` lives in `infrastructure/identity_registration.py`. Its `purge(before: datetime, limit: int) -> bool` reserves at most `min(limit, 500) // 2` deletions for each store independently, attempts both even if one fails, and returns whether either store filled its half-batch. The worker retries full batches with a fair mail turn between them; a single full half-batch must not stop draining.
- `RegistrationEmailQueue.submit_registration(request: RegistrationEmailRequest) -> bool`; `DeliverRegistration.prepare(request) -> PreparedRegistration | None`, `send(prepared) -> None`; `IdentitySmtp.send_registration(recipient: str, token: str) -> None`.
